# Site template — notes for the editing assistant

You may freely edit anything under `src/pages/` (page content and structure), `src/content/` (blog posts — markdown with `title`, `description`, `pubDate` frontmatter), and `src/styles/tokens.css` (the design tokens that control the whole site's colors, fonts, spacing, and radii — change the look here first). Edit `src/layouts/` and `src/components/` only when the user asks for structural or component-level changes. Never modify `astro.config.mjs`, `package.json`, `package-lock.json`, or `tsconfig.json` unless the user explicitly asks — they control the build and breaking them takes the site down.

**Internal links:** the site may be served under a path prefix, so never hardcode a leading `/` in internal links. In `.astro` files, `import { href } from '../lib/links'` (adjust the relative path) and write `href('about/')`, `href('blog/my-post/')`, `href('')` for home. In markdown content, use relative links between posts. External links (`https://…`) and `mailto:` are unaffected.

**Forms:** the platform stores submissions from any form that POSTs to `href('__forms/<name>')` (lowercase letters/digits/dashes) with `application/x-www-form-urlencoded` encoding. Keep the hidden `_hp` honeypot field and the `_next` hidden field (same-site path to redirect to on success) exactly as in `ContactForm.astro`. Field names starting with `_` are reserved platform control fields and are never stored — don't name a real form field with a leading underscore. The site owner reads submissions by asking their assistant (list_form_submissions).

**Images:** uploaded media lives in `public/media/` and is served at the site path `media/<filename>` — reference with `<img src={href('media/logo.png')} alt="…">`. Ask the platform to fetch new images from a URL with the upload_media tool; don't try to write binary files.

**Fonts & performance:** the template ships a fast system-font stack in `tokens.css` and makes zero external requests — that's what keeps sites at ~100 on PageSpeed. If a design genuinely needs a webfont, **self-host it, never link `fonts.googleapis.com`** — a Google Fonts `<link>` is a render-blocking third-party request chain that costs ~10 PageSpeed points on mobile. To self-host: import each `.woff2` into `public/fonts/` with the `import_from_url` tool (it can fetch the files directly from the `fonts.gstatic.com` URLs listed inside the Google Fonts CSS), then add your own `@font-face` rules in `tokens.css` with `font-display: swap`, and `<link rel="preload" as="font" type="font/woff2" crossorigin href={href('fonts/…woff2')}>` in `Base.astro` for the one or two faces used above the fold. Subset to the weights you actually use.
